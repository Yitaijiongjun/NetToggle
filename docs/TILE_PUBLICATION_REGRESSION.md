# custom18：收起期间的重复磁贴发布

基线为用户确认正常的裁剪后版本 `366f41d`（custom15）。对比该基线与 custom17，自动收起 Activity、主题、Intent flags、电话 setter 顺序均未变化，也没有恢复旧的 carrier-change 通知。

custom16 为解决缓存不同步，新增了 SharedPreferences 缓存监听；原来回读完成和操作完成时显式提交磁贴的入口仍保留。两条路径可能对同一内容重复调用 updateTile，快速验证完成时也可能在控制中心收起动画期间提交。它是可以由源码确认的新增发布行为；没有连接手机，不能据此断言所有状态栏闪动都来自它。

本次仅调整磁贴发布，保留切换、验证和缓存同步：

- 删除与缓存监听重复的显式完成刷新。
- 已发送的状态、文字、图标内容不变时，不再提交相同磁贴。
- 开始自动收起后，暂不向 SystemUI 提交磁贴；数据仍按原流程保存至已验证缓存。
- 停止 listening 后停止发布；下一次展开先发布最新缓存。
- 收起 Activity 启动失败时恢复发布，避免锁住磁贴。

不修改窗口主题、启动 flags、收起机制、电话 setter、SIM 解析或验证间隔。四项发布生命周期回归测试覆盖重复回读、收起与重开、启动失败恢复和新 listening 会话；原有电话与最终 Release DEX 检查继续运行。
